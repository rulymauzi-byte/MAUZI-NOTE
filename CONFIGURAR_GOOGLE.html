MAUZI NOTE 3.1 · Asistente de configuración

La app en GitHub.
Las notas en el Drive de cada persona.

Esta configuración la hace solamente el creador de MAUZI NOTE, una vez. Los usuarios solo entran con Google y autorizan su propio Drive. No necesitan proyectos ni configurar archivos.

No hay Firebase. No necesitas firebase-config.js, Firestore, una base de datos tuya ni un servidor privado. Google sí exige registrar qué aplicación va a pedir permiso para guardar archivos. El registro entrega un ID de cliente: identifica la aplicación, no el Drive donde se guardan las notas.

1. Publica el paquete en GitHub Pages

Descomprime el ZIP y sube todo su contenido a tu repositorio, con index.html en la raíz. No subas el ZIP como único archivo. Incluye la carpeta icons, drive-sync.js, google-config.js, el manifiesto y sw.js.

En GitHub abre Settings → Pages → Deploy from a branch → main → /(root) → Save. Espera a que se publique y copia la dirección HTTPS que aparece. Guía oficial de GitHub.

Si actualizas la versión anterior, reemplaza los archivos y elimina del repositorio los antiguos cloud.js, firebase-config.js, firebase.json y los archivos firestore.*. Primero exporta tus notas desde la versión anterior. No elimines bases de datos ni respaldos que ya hayas usado. Esta versión no descarga datos de Firestore; importa una copia desde la app antigua.

Este asistente no envía lo que escribes. Solo calcula las direcciones en tu navegador.

2. Registra MAUZI NOTE en Google

Orden de trabajo: deja esta página abierta en una pestaña. En otra pestaña configurarás Google. Volverás aquí para crear el archivo final. Solo tú, como creador de la app, haces estos pasos.

Abre Google Cloud Console con tu cuenta de creador. Arriba, pulsa el selector de proyectos → Nuevo proyecto. Escribe MAUZI NOTE → Crear. Después selecciona ese proyecto. Si ya tienes un proyecto y un ID para esta app, conserva los mismos: no crees otros innecesariamente.

Esto no convierte tu cuenta en el lugar de almacenamiento. Cada llamada a Drive utilizará el permiso de la persona que inicia sesión, no tus credenciales de administrador.

En APIs y servicios → Biblioteca, busca Google Drive API y pulsa Habilitar. Preparación oficial de Google.

3. Configura la pantalla de permiso

Abre el menú Google Auth Platform / Plataforma de autenticación de Google. Si aparece Comenzar / Get started, púlsalo. Configura Branding / Información de marca: nombre MAUZI NOTE, tu correo de soporte y un correo de contacto. En Audience / Público, selecciona External / Externo para permitir personas que no pertenecen a una misma organización.

Termina el asistente con Siguiente → Información de contacto → Siguiente → Crear, después de revisar y aceptar las condiciones que muestre Google. Luego, en Público / Audience → Usuarios de prueba / Test users → Añadir usuarios, escribe el correo Google con el que harás las pruebas y guarda. Al principio, prueba únicamente con esas cuentas autorizadas.

En Acceso a datos / Data Access → Añadir o quitar permisos / Add or remove scopes, declara estos permisos y pulsa Actualizar / Update → Guardar / Save:

  • openid
  • https://www.googleapis.com/auth/userinfo.email (en el código se solicita como email)
  • https://www.googleapis.com/auth/drive.file

No elijas acceso completo a Drive. El permiso drive.file permite trabajar con archivos creados o autorizados para esta aplicación. Permisos oficiales · Configuración oficial de consentimiento.

En Información de marca, la página inicial será el enlace HTTPS publicado de tu app. La política de privacidad es la dirección que termina en /PRIVACIDAD.html en ese mismo sitio. No pongas una ruta C:\.... Antes de la distribución pública, completa tu nombre y correo real de soporte en esa página. Puedes generar esa copia en el apartado de contacto de abajo.

4. Crea el ID de la aplicación web

En Google Auth Platform → Clients / Clientes → Create client / Crear cliente, elige Web application / Aplicación web.

En Authorized JavaScript origins / Orígenes de JavaScript autorizados, pega solamente el origen que mostró el asistente del paso 1: https://TU_USUARIO.github.io. Sin el nombre del repositorio y sin una barra al final. Este paquete usa el selector de Google en ventana emergente; no requiere una URL de servidor para intercambiar códigos.

Deja vacías las URI de redireccionamiento autorizadas para esta versión con ventana emergente de Google. Escribe un nombre para la credencial, por ejemplo MAUZI NOTE Web. Crea el cliente y copia su Client ID / ID de cliente, que termina en .apps.googleusercontent.com. No copies el secreto. Instrucciones oficiales del ID.

5. Pega un solo dato

Pega el ID debajo y pulsa el botón. Esta página genera el archivo google-config.js por ti. Súbelo a GitHub reemplazando el que estaba vacío. No es tu correo, tu contraseña ni el ID de una carpeta de Drive.

También se puede editar manualmente una sola línea:

window.MAUZI_GOOGLE_CLIENT_ID = "PEGA_AQUI_EL_ID";

Nunca publiques un client_secret, una contraseña, un token de acceso, una clave privada ni respaldos con notas. El ID de cliente público sí debe estar en la app.

6. Comprueba antes de cambiar de teléfono

En GitHub, reemplaza el archivo vacío mediante Add file → Upload files → Commit changes. El archivo debe llamarse exactamente google-config.js, no google-config (1).js ni google-config.js.txt. Si ya habías completado ese archivo, conserva tu ID al actualizar la aplicación. No pegues el ID en index.html.

Espera la publicación de Pages. Abre la app por HTTPS en Chrome o Safari. Si ya la tenías instalada, guarda cualquier nota abierta y revisa Mi cuenta → Estado de la aplicación / actualizaciones. No borres los datos del navegador para actualizar.

  1. Abre MAUZI NOTE desde el enlace HTTPS. Conecta Google y acepta el permiso de Drive.
  2. Crea una nota y pulsa Guardar. Espera Guardado en tu Google Drive ✓.
  3. Abre la misma app en otro navegador o teléfono, conecta la misma cuenta y comprueba que aparece la nota.
  4. Haz una nota sin internet. Verás que está pendiente. Reconecta y confirma que también aparece en el otro teléfono.

Para las notas antiguas usa Mi cuenta → Importar notas de este teléfono. Si estaban en otro archivo o navegador, usa Guardar copia en la versión anterior y Recuperar copia aquí. Las copias JSON no se suben al repositorio público.

7. Después de la prueba: permitir a otras personas

En Google Auth Platform → Público / Audience, revisa Estado de publicación y Publicar aplicación / Publish app. La publicación y la verificación de marca son procesos distintos. Para que el nombre y logo aparezcan a todos en la autorización, revisa Información de marca / Branding → Verificar marca / Verify branding y los requisitos de dominio y política de privacidad que Google muestre. No elimines avisos ni agregues permisos más amplios para saltarte la revisión. Verificación oficial de marca.

Si Google solicita verificar un dominio, usa uno que controles y puedas acreditar mediante Search Console. El origen autorizado de la credencial y la verificación de propiedad del dominio no son lo mismo. Subir los archivos a GitHub no completa automáticamente la verificación de Google.

Errores frecuentes

«Falta el ID de Google»: comprueba que el archivo generado esté en la misma carpeta publicada que index.html y conserve el nombre exacto.

«origin_mismatch»: compara el origen que registraste con el calculado por el botón del paso 1. Debe coincidir en HTTPS y dominio; no debe incluir el nombre del repositorio.

«access_denied»: si está en pruebas, comprueba que esa cuenta figure en Usuarios de prueba. Revisa también que la persona acepte el permiso y que su organización no lo bloquee.

«Google Drive API no habilitada»: activa la API en el mismo proyecto en que creaste el ID.

«Google no ha verificado esta aplicación»: revisa el estado de publicación y el Centro de verificación. No indica que debas pagar ni proporcionar la contraseña a MAUZI NOTE.

Qué significa «sincronizar» en este paquete

La app recuerda y abre la copia del teléfono. Al conectar Google descarga tus notas y sube los cambios pendientes. Después sincroniza al guardar, al volver a la app y aproximadamente cada minuto mientras está abierta y autorizada.

Google puede pedir Conectar Google otra vez. Esta es una app estática, sin servidor que conserve credenciales privadas. Los permisos de acceso son temporales y se solicitan mediante un toque del usuario. La app no guardará secretos en GitHub ni fingirá que sincronizó cuando el permiso venció. Modelo de autorización de Google.

La sincronización no se ejecuta permanentemente si la app está cerrada. Una nota pendiente solo está en el teléfono; debes conectarlo para que llegue al nuevo. Si alguien borra manualmente la carpeta MAUZI NOTE de Drive, vacía la papelera de Drive, pierde permisos o espacio, no existe garantía de recuperación. Conserva respaldos independientes.

Las versiones se guardan como archivos JSON de la aplicación dentro de Mi unidad → MAUZI NOTE, no como documentos de Google Docs. No se borran automáticamente. El historial aumenta el espacio usado en el Drive de esa persona; revisa su almacenamiento.

Mantén el mismo proyecto de Google e ID de cliente. Cambiar a un proyecto nuevo puede impedir que la nueva app vea los archivos autorizados para la anterior. Antes de cambiar la configuración, exporta respaldos.

Contacto para la página de privacidad

Completa los datos reales del responsable de la aplicación. Este botón solo genera un archivo local para que sustituyas PRIVACIDAD.html en tu repositorio. Revisa el contenido antes de publicarlo.

La instalación

Android: abre el enlace con Chrome e instala desde la app o el menú del navegador. iPhone: Safari → Compartir → Añadir a pantalla de inicio. Espera «Lista sin conexión» para cerrar la app. En modo instalado se ocultan los botones Instalar. Las cuatro Biblias siguen integradas sin internet.

No se ha vinculado este paquete a un proyecto real de Google. Las pruebas de la lógica usan respuestas simuladas de Google Drive y almacenamiento simulado, además de pruebas de interfaz y lectura bíblica sin red. La instalación y persistencia nativa deben comprobarse en el sitio publicado. Debes completar el paso 6 con tu proyecto real antes de distribuirla para guardar información importante.
